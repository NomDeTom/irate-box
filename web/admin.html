Add-ons

        

          The hub works without any of these. Adding one installs it and starts it; removing one
          stops it and takes its service away, and keeps its data, so adding it back finds
          everything where it was. Each runs the installer, which takes a few minutes on this
          board and restarts the hub part-way through.
        

        

        

          
          

        

        

          Installer output
          

        


        
Web add-ons

        

          Apps that run in the visitor's browser, added here in a minute with no installer and no
          restart. Each is served on its own address (this box, port 8090),
          so it cannot reach this page, the hub's settings or anything else on the box. An added one
          starts off: switch it public or private when you are ready. The Library
          pane's Apps keeps it current, at the commit the hub's code checked unless you choose the newest.
        

        

        
The catalogue

        
Add-ons this hub's code offers, each pinned to a commit that was checked.

        

        

          Add one by pasting its manifest
          

            
⚠️ Only do this with a manifest you have read and from someone you trust.

            
A pasted manifest is not checked by anyone but you. It downloads someone else's code and
            serves it to everyone on this box's network who opens it, under this box's name. That code
            can show them anything, ask them for anything, and send what they type to wherever its
            manifest lets it connect. It cannot reach this page or the box itself: that much the hub
            enforces. If you are not sure, use the catalogue instead.

Clock

        

          What keeps the box's time, what happened to it at this boot, and a clock module on I2C if
          there is one. Boards like this one have no clock of their own: without the network or a
          module, the time comes back wrong after a power cut. Looking for a module only reads the
          I2C buses; setting one up uses the kernel's driver where there is one, and never switches
          on charging.

    Firmware
    
        
    
          Meshtastic's release files kept on the box for the web flasher, so a radio can be flashed
          with no internet. Only the boards you tick are kept (a few MB each, per release); "all
          boards" is about 600 MB a release. Checked on the library's schedule, whenever the box has
          internet. The firmware's source code is a mirror like any other repository (Git → Mirrors);
          the build cache is with the builds (Git → Builds). To build your own from the mirror, for
          boards a release doesn't cover or from a fork: the Firmware Factory.
        
    
        
    
        
    
        
    
          
          
          
          
          
          
          
    
          
        
    
        
    
        
    
          
          
        
    
        
    Kept
    
        
    
      
    

      
    
        
    Mirrors
    
        
    
          Repositories the box keeps from an upstream on the internet, by a policy: which branches,
          how many releases, how much history, and their submodules. The librarian checks them on
          its schedule (Schedule and token). Each is read-only on the box, and shows on the Git page
          as a card of its own. New mirrors are public (anyone on the network can browse and clone
          them, as on the internet); choose Private to keep one behind the admin login.

    Toolkits
    
        
    
          Sets of tools the box keeps in a local repository of its own, fetched while it has
          internet and installed from there with none: for debugging, building, capturing traffic
          and checking its security. Each installs only when you ask, with its services left
          stopped, and is removed again after the time you choose (a day, unless you change it).
          The library keeps each one current on its schedule (Schedule and token).
        
    
        
    
        
    
          
          
          
        
    
        
    
        
      
        
      
        
      By USB stick
      
        
      
          Carry kits to a box that never goes online: copy a cached kit onto a stick here, then import
          it there. The stick also carries Debian's signed indexes for its packages, and an import
          checks every package against them with the box's own keys before anything is kept.
        
      
        
      
        
      
        
      
        
      Add a toolkit of your own
      
        
      
          Any Debian packages this box's package lists know, kept, refreshed and removed like the
          kits above. Each name is checked before the kit is kept.

      Git
      
        
      
          The repositories on this box, a card each. /git/ is public: anyone on
          the network can browse and clone. /git-private/ is behind the
          admin login. Who may push, and whether a push is built, is each repository's own: Manage
          on its card. Clone with git clone http://<this box>/git/<name>.git; git
          asks for the login when it is needed.
        
      
        
      
          What the words mean
          
      
            
      Public, Private
      Where it lives: /git/ (anyone on the network sees it) or /git-private/ (only with the admin login). Moving it changes its clone URL.
      
            
      Who pushes
      Anyone; only the admin; or nobody (read-only). The hub decides each push; git's own setting is the backstop.
      
            
      Mirror
      A copy of a repository on the internet, kept to a policy by the librarian (Library → Mirrors). Read-only here.
      
            
      Builds
      A push to a private repository that only the admin pushes to, whose commit has a .irate-ci.sh, is built on the box (Builds, below), if its switch is on.

      Firmware Factory
      
        
      
          Build Meshtastic firmware here, from the box's own copy of its source (a mirror, or a
          private repository such as a fork): choose a release or a branch, then the boards. Builds
          run one at a time, at the lowest priority, as the builder (Git → Builds), and each one's
          use of time, memory, disk and heat is recorded, so the estimates below come from this box.
          A family's first build here downloads its toolchain; after that it can build offline.
        
      
        
      Paused: nothing new starts until you resume (a build under way finishes).

          What these words mean
          
        
            
        Client
        The box joined to your WiFi, as a laptop would: its way to your network and the internet.
        
            
        Hotspot
        The box's own WiFi network, which guests join (an "access point").
        
            
        Beside the client
        Some radios can be both at once: on your WiFi, and running the hotspot as a second network.
        
            
        Takes the radio
        A radio that can only do one: running the hotspot means leaving your WiFi.
        
            
        Channel
        The slice of the WiFi band a network uses. A radio that can only use one channel at a time makes its hotspot follow your WiFi's.
        
            
        Managed by
        The program on the box that looks after a device's connection (NetworkManager, wpa_supplicant, …). irate-box asks it, and doesn't take over.
        
            
        Signal
        How strongly your WiFi is heard, in dBm: closer to 0 is stronger. About −50 is excellent, −70 weak, −80 barely there.

              The hotspot's own WiFi
              
        
              
          How guests join the box's own hotspot: open to all, or encrypted so someone listening nearby
          cannot read what guests do. Encryption shuts out older devices, so this is a trade between
          who can join and what is protected. The hotspot itself is still to come (the hotspot add-on):
          the choice is kept and applied when it is set up. What the radios here allow comes from

                Updates
                
        
                Installed: …
                
        
                
          Checking asks the repository this box was installed from what is new. Fetching then
          verifies that version and downloads what its installer will need, so nothing is fetched
          half-way through an install. Installing reruns the installer with the same options. Apps,
          books, data and the password are kept. The hub restarts part-way through, and this page
          reconnects by itself.
        
                
        
                Not checked yet.
                
        
                When an update fails, the Updates doctor can say why.
                
        
                Automatic updates
                
        
                
          The librarian can look for updates by itself, on its hourly round, and take them as far
          as you choose. An install is only ever of a version that passed verification, inside
          the hours you set, with nobody on the hub and nothing else running; the hub restarts
          part-way through. A version that fails verification waits for you here.

                    Backup and sync
                    
        
                    
          Download a backup of the hub's state: notes, saved
          work, board, shoutbox, settings, the library's sources and the uptime clock. ZIM books
          and archived versions are left out (they come from their sources), as is the GitHub token,
          and so is Syncthing's identity: restored, Syncthing gets a new device ID and its peers
          pair again.
        
                    
        
                    
          ⚠ Includes Syncthing's private keys:
          download a backup with
          Syncthing's identity (key.pem, https-key.pem,
          config.xml), so a restored box keeps its device ID. Whoever holds that file
          can pose as this box to its Syncthing peers: keep it like a password.
        
                    
        
                    Set up another box
                    
        
                    
          An offline kit: everything another box needs to be set up as this one is, with no
          internet — this box's code, its apps, the release files it keeps (the terminal, notes), and
          its books if you like. One file to download; unpack it on the new box (a USB stick will
          do) and run sudo ./setup.sh in it. Made for boards like this one; Debian's own
          packages still come from the new box's system. Anything this box does not keep is fetched
          if it has internet, and otherwise left for the new box to fetch.

                      Security doctor
                      
        
                      
          A read-only audit of how the system underneath is set up, including what the hub found
          when it was installed: the notes add-on, the web server's settings, links and root-written
          files in the hub's folders, unit sandboxing, secrets on command lines and at rest, git
          pushes, sudo rules, accounts and the kernel's protections. It changes nothing and has no
          buttons beyond this one; each line says what to do by hand. What a guest can reach, and the
          fixes you can choose, are on Security. Also from a shell:
          sudo /opt/irate-box/irate-box secdoctor.

          The update doctor looks at what an update depends on — the network, names, the clock,

                              Install anyway
                              
        
                              
          When the fetched version did not pass verification and you know why — the check itself
          can be what is wrong, as when an update changes how the code is laid out — it can be
          installed regardless. The installer runs as it always does and stops on its own errors;
          the checks that failed are skipped. Only for a version you trust: the one fetched from
          the repository this box was installed from.
