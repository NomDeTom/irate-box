      Add-ons
      
        
      
          The hub works without these add-ons. Install an add-on to start its service. Remove it to stop its
          service and uninstall the service. Removal keeps its data. Install the add-on again to use that data.
          Installation can take several minutes on this board. The installer restarts the hub server during the
          installation.

      Web add-ons
      
        
      
          Web add-ons run in the visitor's browser. The box adds them without an installer and without a restart.
          Each add-on has its own address (this box, port 8090). The hub prevents an
          add-on from opening this page or the hub settings. An add-on can reach the services that its manifest
          declares, such as the MQTT broker. A new add-on is disabled. Select Access to give it
          to guests, users or administrators. The Apps list on this page keeps the add-on current, at the commit
          that the box's code checked, unless you select the newest.
        
      
        
      
        
      The catalogue
      
        
      The box offers these add-ons. Each add-on is pinned to a commit that the box checked.
      
        
      
        
      
          Add one by pasting its manifest
          
      
            
      ⚠️ Add a pasted manifest only if you have read it and you trust its author.
      
            
      Nobody else checks a pasted manifest. The box downloads someone else's code. The box serves that code
            under its own name to everyone on the box's network who opens it. The code can show anything and ask
            for anything. It can send what people type to the services that its manifest declares. The hub
            prevents it from opening this page or the box itself. If you are not sure, use the catalogue.

      Recovery and monitoring
      
        
      
          Set how long crash snapshots are kept and when the box restarts after a freeze. The
          Box doctor shows the results.
        
      
        
        
      
          
      SD card writes
      
          
      An SD card wears with every write. The box writes a file only when it changes. It keeps live
            reports in memory. It adds to histories and does not rewrite them. The box can write less often. A crash
            or power failure can then lose changes made since the last write. Select how many changes the box can
            lose. At every level, the box writes user data and settings as they change.
      
          
      
          
      
        
      
        
        
      
          
      Automatic recovery
      
          
      Set crash snapshot retention and frozen-system restart. The uplink watchdog repairs the box's network
            connection and reboots the box for it: Network → Network recovery.

          Source access: GitHub token and rate limit 
          
        GitHub token
        
          
        
            Use a token only for "GitHub Actions artifacts". GitHub requires a sign-in to download them, also from
            public repositories. A fine-grained token with read-only access to public repositories is enough. The
            box stores the token. Only the hub can read it. The page never shows it again.
            
          
        
          
        
            
            
        
              
              
            
        
          
        
          
        Adapt to the rate limit
        
          
        
            GitHub lets this box send 60 requests an hour without a token and 5000 with a token. Adapt asks GitHub for
            its request limit. The librarian then keeps its scheduled checks to a budget just under that limit. When the
            hourly budget is spent, the checks wait. If GitHub refuses several requests in a row, the box halves the
            budget. A clean run gives some budget back. Adapt works with or without a token.

          Git
          
        
          
          The box keeps these repositories, one card each. /git/ lets guests browse and clone.
          /git-private/ needs the administrator sign-in. Each repository sets who can push and
          whether a push starts a build: select Manage on its card. To clone, run

          Repository terms
          
          
            
          Guests, Administrators
          Where the repository lives: /git/ (guests can browse and clone it) or /git-private/ (the administrator sign-in is required). Moving a repository changes its clone URL.
          
            
          Push permission
          Guests, administrators only, or nobody (read-only). The hub decides each push. Git also enforces the setting.
          
            
          Mirror
          A copy of a repository on the internet. The librarian keeps it to a policy (Mirrors, below). It is read-only here.
          
            
          Builds
          A push starts a build on the box (Builds, below) only if four conditions are true. The build switch is on. The repository is in the administrators-only area. Only an administrator pushes to it. The commit has a .irate-ci.sh file.

              Network terms
              
                
                
                Client
                The box joins your WiFi as a laptop does. This is the box's way to your network and the internet.
                
                
                Hotspot
                The box's own WiFi network. Guests join it (an "access point").
                
                
                Concurrent client and hotspot
                Some radios can serve the client connection and the hotspot at the same time. The hotspot is a second network.
                
                
                Exclusive hotspot radio
                This radio can do one task only. To run the hotspot, the box must leave your WiFi.
                
                
                Channel
                The part of the WiFi band that a network uses. A radio that can use one channel at a time makes its hotspot follow the channel of your WiFi.
                
                
                Managed by
                The program on the box that manages the connection of a device (NetworkManager, wpa_supplicant, …). irate-box asks that program and does not take control.
                
                
                Signal
                How strongly the box receives your WiFi, in dBm. A value closer to 0 is stronger. About −50 is excellent, −70 is weak, −80 is barely usable.

                The hotspot
                
            
                
              The hotspot is the box's own WiFi network for guests. Its address is 192.168.4.1. In captive-portal DNS
              mode, every name leads to the hub. The box adapts to its radios. It uses a separate radio if one exists. If
              the radio supports it, the hotspot runs on its own channel beside your WiFi. Otherwise it follows the
              channel of your WiFi. Select below how guests join: open or encrypted.

                Hotspot security
                
            
                
              The hotspot can be open or encrypted. An open hotspot lets anyone join. An encrypted hotspot prevents a
              person who listens nearby from reading what guests do. Encryption excludes older devices. The choice applies
              the next time you switch the hotspot on above. That section also shows what the radios support. This is a
              setup decision, and the setup tour links here.
            
                
            
                
            
                
              
                
                
                
              
                
              
              
                
                
              
              
            
                
            
                  
            
                  
              
              
            
                  
            
                  
            
                  Guest internet access
                  
            
                  
              This setting decides whether guests on the hotspot can use the box's connection to reach the internet. The
              levels run from no access to full access. The default is the safest. Each level says what it opens. Guest
              traffic leaves as the traffic of the box, so what guests do online comes from your connection. At every level,
              the box keeps guests out of your own network and the box's Tailscale. It lets them out by the hardware address of
              their device. It does not let them look up names before they pass the sign-in page. You can turn off each of
              these on Security. The doctor warns while one is off.

                  Visitor data
                  
        
                  
          The box counts different devices, today and this week, for the People tile. It never records who they were. A
          helper reads the network addresses of the devices that the box has seen. It hashes each address with a random
          salt for the day and a random salt for the week. The helper holds the salts only in memory and discards them when
          the day or week ends. No hash can be reversed to a device or matched to another day. The box writes only the two
          numbers, and deletes them at reboot. Phones that use a random address can count more than once, so the numbers
          are approximate. If you turn this off, the helper does not run. Signed-in names show only if each person lets the box
          show it on their account page.
        
                  
        
                  
          
        
                  
        
                  
        
                  HTTPS
                  
        
                  
          The box can serve every page over HTTPS too, with a certificate of its own. Phones and
          computers that install the box's certificate (from /certificate)
          then use HTTPS when they connect. Other people on the WiFi cannot read the administrator
          password. The box's certificate authority is limited to this box's names. A device that enforces the
          limit rejects other sites. Plain HTTP stays on, for other devices and the hotspot's sign-in.
        
                  
        
                  Checking…
                  
        
                  
          
          
          
          
          
        
                  
        
                  
        
                  
        
                  
          Use your own certificate
          
                  
            Use this for a domain that you own, with a certificate made elsewhere. The box has no public address, so use
            a DNS challenge: certbot certonly --manual --preferred-challenges dns, or the tool of your DNS
            host. Devices then trust the box without an installation. Paste the full chain (the certificate, then its
            intermediates) and the unencrypted private key. The box checks that the certificate and key match, that the
            certificate has not expired, and that the chain reaches a known CA. The box never replaces the certificate
            by itself. Renew it before it expires.
          
                  
          
                  This page uses plain HTTP. The private key would cross the network in clear text. Paste the key over HTTPS, or from a device on a cable.

              How an update goes
              
                      
                Check asks the repository that the box was installed from what is new. Download verifies that version and
                downloads what its installer needs, so the box downloads nothing in the middle of an installation. Install
                runs the installer again with the same options. The box keeps apps, books, data and the password. The hub
                server restarts during the installation, and this page reconnects by itself.
              
                      
              
                      
                The librarian can look for updates by itself in its hourly round, and take them as far as you select. The
                box installs only a version that passed verification. It installs inside the hours you set, when nobody
                uses the hub and nothing else runs. The hub server restarts during the installation. A version that fails
                verification waits for you here.

                      The update cache
                      
          
                      The cache holds a copy of the hub's code and the downloads for updates. After you clear it, the
            next check starts afresh. Clear it when the Updates doctor finds the cache broken.

          Use this when the downloaded version did not pass verification and you know the reason. For example, the

          errors. It skips the checks that failed. Use this only for a version that you trust: the version downloaded
          from the repository that the box was installed from.
