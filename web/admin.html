    Add-ons
    
        
    
          The hub works without any of these. Adding one installs it and starts it; removing one
          stops it and takes its service away, and keeps its data, so adding it back finds
          everything where it was. Each runs the installer, which takes a few minutes on this
          board and restarts the hub part-way through.

    Web add-ons
    
        
    
          Apps that run in the visitor's browser, added here in a minute with no installer and no
          restart. Each is served on its own address (this box, port 8090),
          so it cannot reach this page, the hub's settings or anything else on the box. An added one
          starts off: open it to everyone, to users or to the admin when you are ready. The

          Add one by pasting its manifest
          
    
            
    ⚠️ Only do this with a manifest you have read and from someone you trust.
    
            
    A pasted manifest is not checked by anyone but you. It downloads someone else's code and
            serves it to everyone on this box's network who opens it, under this box's name. That code
            can show them anything, ask them for anything, and send what they type to wherever its
            manifest lets it connect. It cannot reach this page or the box itself: that much the hub
            enforces. If you are not sure, use the catalogue instead.

          What these words mean
          
          
            
          Client
          The box joined to your WiFi, as a laptop would: its way to your network and the internet.
          
            
          Hotspot
          The box's own WiFi network, which guests join (an "access point").
          
            
          Beside the client
          Some radios can be both at once: on your WiFi, and running the hotspot as a second network.
          
            
          Takes the radio
          A radio that can only do one: running the hotspot means leaving your WiFi.
          
            
          Channel
          The slice of the WiFi band a network uses. A radio that can only use one channel at a time makes its hotspot follow your WiFi's.
          
            
          Managed by
          The program on the box that looks after a device's connection (NetworkManager, wpa_supplicant, …). irate-box asks it, and doesn't take over.
          
            
          Signal
          How strongly your WiFi is heard, in dBm: closer to 0 is stronger. About −50 is excellent, −70 weak, −80 barely there.
          
          
          
        
          
        
          
        
            

        
            The hotspot
            
        
            
          The box's own WiFi, for guests: address 192.168.4.1, every name answered with the hub. It
          fits itself to the radios here: a radio of its own if there is one, beside your WiFi on a
          channel of its own where the radio can, following your WiFi's channel where it can't. How
          guests join (open or encrypted) is chosen on Security.

                  What the box keeps about visitors
                  
        
                  
          A count of different devices, today and this week, for the People tile: never who they
          were. A helper of its own reads the network addresses of the devices the box has seen, hashes
          each with a random salt made for the day (and one for the week) and held only in its memory,
          and throws the salt away when the day or week ends, so no hash can be turned back into a
          device or matched with another day's. Only the two numbers are written, and they go at
          reboot. Phones that use a random address may count more than once, so the numbers are
          approximate. Off, the helper doesn't run at all. Signed-in people's names show only if each
          of them says so, on their own account page.
        
                  
        
                  
          
        
                  
        
                  
        
                  HTTPS
                  
        
                  
          The box can serve every page over HTTPS too, with a certificate of its own: phones and
          computers that install the box's certificate (from /certificate)
          then talk to it privately, and the admin login can't be read off the WiFi. It can vouch
          only for this box. Plain HTTP stays as it is, for everyone else and the hotspot's sign-in.
        
                  
        
                  Looking…
                  
        
                  
          
          
          
          
          
        
                  
        
                  
        
                  
        
                  
          Use your own certificate
          
                  
            For a domain you hold, minted elsewhere (the box has no public address, so a DNS
            challenge: certbot certonly --manual --preferred-challenges dns, or your DNS
            host's own tool). Devices then trust the box with nothing to install. Paste the full
            chain (the certificate, then its intermediates) and its unencrypted private key. The
            box checks that they match, that it hasn't expired and that the chain reaches a known CA,
            and never replaces it on its own: renew it before it expires.
          
                  
          
                  This page is on plain HTTP: the private key would cross the network in clear. Paste it over HTTPS, or from a device on a cable.

                              Import a scan
                              
        
                              
          OpenVAS (Greenbone) or nmap, run from a PC on the hotspot against the box: the outside view,
          including software debsecan can't see. Export the report (OpenVAS: XML or CSV; nmap:
          nmap -sV -oX report.xml <box>) and choose it here. It is read in this browser;
          only what it found is sent to the box, and kept until the next import of the same kind.

                                  Updates doctor
                                  
        
                                  
          The update doctor looks at what an update depends on — the network, names, the clock,
          GitHub, free space, the cached copy, the package sources — and says what is wrong and what
          to do about it. For the box itself (services, Kiwix, an install that stopped), see the
          Box doctor; to check for and install updates, Updates.
        
                                  
        
                                  
          
          
        
                                  
        
                                  
        
                                  
        
                                    

        
                                    Install anyway
                                    
        
                                    
          When the fetched version did not pass verification and you know why — the check itself
          can be what is wrong, as when an update changes how the code is laid out — it can be
          installed regardless. The installer runs as it always does and stops on its own errors;
          the checks that failed are skipped. Only for a version you trust: the one fetched from
          the repository this box was installed from.
